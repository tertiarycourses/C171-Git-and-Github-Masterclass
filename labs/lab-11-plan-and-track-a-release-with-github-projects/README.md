# Lab 11 — Plan and Track a Release with GitHub Projects

**Exam domain:** Manage Projects with GitHub (5–10%)

**Objective:** Coordinate scope, ownership, timing and progress for a release.

## Scenario

The CourseTrack Pro team needs one view of features, defects and release readiness.

## Deliverable

A GitHub Project with table, board and roadmap views plus fields, workflows and insights

**Tools:** GitHub Projects, issues, milestones, labels, saved replies, Excel workbook

## Detailed procedure

1. Create a project named CourseTrack Pro Release 1.1.
2. Add existing issues and pull requests and create two draft planning items.
3. Create Status, Priority, Iteration and Target date fields.
4. Configure table, board and roadmap views for different stakeholder questions.
5. Group or slice one view by owner, status or priority.
6. Configure a built-in workflow that moves closed items to Done.
7. Create a milestone and associate the release issues or pull requests.
8. Create an insight chart and interpret one bottleneck or workload imbalance.
9. Export the release inventory and observations into the Excel workbook.

## Evidence workbook

Open `Lab-11-Evidence-Starter.xlsx` before you begin. Record every action, result, URL or screenshot reference, status, and reviewer note. The completed workbook is a worked example only; replace sample URLs with your own evidence.
