# Lab 08 — Coordinate Work with Issues, Discussions and Pages

**Exam domain:** Collaborate Using GitHub (10–15%)

**Objective:** Choose and configure the right collaboration object for work, knowledge and publishing.

## Scenario

Northstar needs structured bug intake, a Q&A area and a lightweight project site.

## Deliverable

Issue form, triaged and cross-linked issue, Q&A discussion, notification plan and GitHub Pages site

**Tools:** Issues, Discussions, GitHub-Flavored Markdown, notifications, Gists, Wikis, GitHub Pages, Excel workbook

## Detailed procedure

1. Create labels for bug, documentation, priority-high and good-first-issue.
2. Create an issue template or issue form for reproducible bugs.
3. Open a sample issue whose body uses GitHub-Flavored Markdown deliberately: a heading, bold and italic emphasis, a bulleted and a numbered list, a table, a block quote, a link and an image.
4. Add a fenced code block with a language identifier and confirm the syntax highlighting; add an inline `code` span and a - [ ] task list, then tick one item and observe the progress indicator.
5. Use a slash command such as /table or /code in a comment field and record what it inserted.
6. Assign the issue, label it and add it to a milestone.
7. In a comment, cross-link a second issue with #<number>, reference a commit by pasting its seven-character SHA, and confirm both render as autolinked references.
8. @mention yourself and, if the repository is in an organisation, a team, and explain how mention notifications differ from watching the repository.
9. Enable Discussions and open a Q&A discussion with a clear title, a category and an accepted-answer plan.
10. Configure repository watch settings and compare All activity, Participating and @mentions, Custom and Ignore subscriptions.
11. Create a saved reply for a common triage response and use it once.
12. Use global search and then a context search inside the repository with a qualifier such as is:issue label:bug, and record how the results differ.
13. Create a public or secret gist and compare it with a repository Wiki page.
14. Create docs/index.md on a branch, commit it and publish GitHub Pages from the selected branch/folder.
15. Verify the published Pages URL and record visibility implications.
16. Record URLs, screenshots, the rendered Markdown and the object-selection rationale in Excel.
